## 贴顶下拉补位：修「进页直接下拉不显示」（2026-09-21 第四批）

用户反馈：「首次下拉页面时没有显示出来，得往上滑再下拉才有显示。我们来探讨一下」

### 定位
不是 bug，是纯方向方案的固有天花板：页面**已经在顶部**时 `scrollTop` 就是 0，小程序拿不到负值，
「到顶后继续拖」根本没有事件 → `delta` 恒为 0 → `searchScrollIntent` 永远返回 none。
用户上滑一段（0→150）再拉回 0 才产生 `delta = -150`，所以那条路径能触发。诊断图已给用户看过。

### 选型（AskUserQuestion，用户选「补触摸手势」）
- A 补触摸手势（**选中**）：页面根 capture-bind 触摸事件，只有贴顶那一段接管。
- B 原生下拉刷新（onPullDownRefresh）：会闪转圈 + 双重位移，用户上次已否。
- C 导航栏搜索图标点按入口：零风险但丢掉手势感。
- D 改 scroll-view + `refresher-default-style="none"` 自绘：最正统，但整页滚动载荷全要重算。

### 实现
- `utils/search-reveal.ts` 新增纯函数 `topPullIntent({dy, top, shown, blocked})` +
  常量 `SEARCH_PULL_TRIGGER_PX=28`、`SEARCH_PULL_TOP_TOLERANCE_PX=2`。
- `behaviors/search-reveal.ts` 新增字段 `searchTouchY`、方法 `onSearchTouchStart/Move/End`、
  `SearchTouchEvent` 最小事件类型（只取 `touches[0].clientY`）。
- 两个列表页根节点（`<view class="page">`）挂
  `capture-bind:touchstart/touchmove/touchend/touchcancel`。

### ⚠️ 关键坑（已写进技能 §7.4）
- **必须 `capture-bind`，不能用 `bind`**：Vant `swipe-cell/index.wxml` 有
  `catchtouchmove="{{ catchMove ? 'noop' : '' }}"`，拖动中会阻断冒泡 —— 冒泡阶段的监听收不到
  「手指落在卡片上」的 move，而贴顶下拉恰好全落在卡片上。捕获阶段先于子节点触发，不受 catch 影响
  （Vant 自己也是用 `capture-bind:touchmove` 避开内部元素）。
- **`top` 必须在 touchmove 里现读 `searchLastTop`**，不能用 touchstart 时快照：用户从列表中部
  一路拉回顶部时手指还没松开，现读才能接住同一段手势的后半程（有单测钉住）。
- **判定成功即清 `searchTouchY`**（一次手势只露一次）；已露出 / 多选态时 touchstart 直接不记起点。
- iOS 贴顶下拉的橡皮筋回弹改不掉，接受；回弹若上报负 scrollTop，已被两侧 `Math.max(0,·)` 归零，
  不会误判成「下翻收起」。

## 搜索栏改「跟手下拉 + 松手吸附」（2026-09-21 第五批，对齐微信聊天列表）

用户口径：「现在是拉到阈值才整体弹出，没有 iOS 橡皮筋回弹感；要做成手指下拉多少它露多少，
松手按距离和速度决定吸附或回弹，参考微信聊天列表顶部搜索框」。并要求记住改动、留回退点。

### 位移模型换过一次（关键）
- 旧：`.search-slot` 在文档流里，`height: 0 → 96rpx` 撑开 + 淡入（"整体弹出"）。
- 新：**搜索栏绝对定位在 `.pull` 上方一个槽位高处**，`.pull` 承载全部页面内容，
  用 `transform: translate3d(0, Npx, 0)` 把搜索栏带进视口 → 观感是"搜索框从上方滑入、内容整体下移"。
  好处：位移不参与布局（无重排），且"位移量"天然就是跟手量。
- ⚠️ `.pull` 上的 transform 会给后代创建包含块 → 页面里不能有依赖它定位的 `position: fixed`
  元素（fab / 多选操作条 / 撤销条都在 `.page` 之外，安全）。`.pull` 必须包住搜索栏与**全部**内容。

### 手感参数（全在 utils/search-reveal.ts 顶部）
| 常量 | 值 | 作用 |
|---|---|---|
| `PULL_ACTIVATE_PX` | 6 | 激活死区：横向滑删带的纵向漂移不该让整页抖；越过它后仍严格 1:1 |
| `PULL_OVERSHOOT_DAMPING` | 0.35 | 拉过槽位高后超出部分只按 35% 计入（"还有一点余量"） |
| `PULL_MAX_RATIO` | 1.6 | 位移封顶（槽高的倍数），防一路拉出半屏 |
| `PULL_SNAP_RATIO` | 0.4 | 松手时拉出量过槽高 40% 即吸附到全开 |
| `PULL_SNAP_VELOCITY` | 0.3 | 甩动速度门槛（px/ms），速度优先于距离 |
| `PULL_SETTLE_MS/EASING` | 340ms / `cubic-bezier(0.22,1.18,0.36,1)` | 吸附曲线，y>1 制造轻微过冲＝橡皮筋感 |

### 编排要点
- **位移与 transition 必须拼进同一次 setData**（`pullStyleOf(offset, dragging)`）：跟手期间
  `transition: none`，松手换成吸附曲线。拆成两个 data 字段会让"关过渡"与"改位移"落在不同帧 →
  跟手第一段被曲线吃掉，看着慢半拍。这与 Vant swipe-cell 把两者拼进同一个 wrapperStyle 同理。
- `applyPullOffset(offset, shown)` 是位移/展开态的**唯一出口**（吸附、滚动收起、空闲收起、切页复位全汇到这里），
  并顺带把未完成的手势丢弃（`searchTouchY = null`），否则残留 move 会继续往画面写值。
- 接管判定惰性放在 `touchmove`：不只服务"起手就贴顶"，还要接"从列表中部一路拉回顶部"的手势
  （起点在中部时 dy 里混着一大段页面滚动，只有等页面真的贴顶了才起算，位移才不会突变）。
- `onSearchTouchEnd` 的**回弹一支刻意不走 `hideSearch`**：它会被"正在使用/不可滚动"拦下，
  位移就停在半路（手指已松、内容卡在中间）。回弹只表达"这段手势没拉够"。
  唯一例外：`searchUnscrollable` 时回弹成露出（那也是"常驻栏被多选态藏起来后"唯一能把它找回来的路径）。
