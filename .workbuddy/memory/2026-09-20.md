## 修「切页回来后该记录左滑没反应」（2026-09-20 下午，用户报告）

- 记录残留的三个原因（都修了）：① `onSwipeOpen` 的「多选态兜底」分支先 setData 写了记录、再因 `if (selecting) return` 跳过清记录的 `enterSelect` → 记录永久留下；② `closeAllSwipes()` 的 `if (!ids.length) return;` 早退，把「清 openSideMap」一起跳过 → 脏记录跨页存活、onShow 的收口也失效；③ 关闭只依赖 `close()`，而 `selectComponent` 查不到实例时 `inst?.close?.()` 静默失效，组件内部 offset 卡在滑开位。

## 再修「快速来回切页后那一行滑不动」（2026-09-20，用户反馈上一版没解决）
上一版只修了"记录脏"，这次定位到**另有两条独立成因叠在一起**，三条都会单独造成同一现象：
1. **强制收回的还原太早**（120ms < Vant 0.6s 过渡）：宽度从 0 弹回 144 时，`rightWidth` observer 又看到 `offset≠0` → 再 `swipeMove(newWidth)`；若那一瞬内部 offset 未归零，这行被**重新滑开**，再叠 onHide 的收回，两次过渡互相打断 → 卡半开位。快速切页正好把"收起动画中"和"强制收回"叠在一起。
   → 常量拆两个：整页级 `SWIPE_RESET_FALLBACK_MS = 780`（必须 > 620），单行补清 `SWIPE_ROW_RESET_MS = 120`。
2. **slot 节点结构变化会触发 Vant 宽度 observer**：右槽两块写成 `wx:if`/`wx:else`，glass-easel 重展开插槽时把 header 里的 width 又写一遍 → 正在收起的行被按新宽度滑开。
   → 两个 slot **常驻 DOM**，显隐改用 `.swipe-act--hidden`，右槽用**两个并列 view**（`wx:else` 也是换节点）。
3. **`selectComponent('#swipe-<id>')` 不保证命中子组件**（id 选择器静默返回 null）→ `inst?.close?.()` 什么都不做而记录已清。
   → 新增 `collectOpenCells()`：从 `getCurrentPages().at(-1).$$` DFS 找 `typeof node.offset === 'number' && node.offset !== 0` 的实例（子节点在 `__wxElement.childNodes`，顶层无 `parent`），`closeAllSwipes` / `resetSwipes` 两处都用；失败退回按 id 收。
   另修 `onCellTouchEnd` 的补清缺口：`bind:touchend` 在外层、`onClick` 是 catchtap，手指移出卡片再抬起不触发 click → 该分支改走 `forceCloseRow`（清记录 + 宽度归零）。

### 第 3 条：真因 = setData 批次竞争（前三次全没命中）
用户的补充现象给出了决定性线索：「**能看到一小部分删除的按钮正往回缩**」
+「**滑其他记录，该记录才快速回退**」。后者正是 Vant `onDrag` 里
`ARRAY.filter(item => item !== this && item.offset !== 0).forEach(item => item.close())` 的**唯一来源**，
直接证明 **offset 停在非 0**；前者是半开位残留。合起来只能是：

> **`resetSwipes` 的"两槽宽度归零一帧 → 下一帧还原"若两次 setData 落在同一渲染批次，
> Vant 的 `swipeMove(0)` 会被宽度 observer 的 `swipeMove(newWidth)` 覆盖**
> （两者都写 `this.offset = range(offset, -rightWidth, leftWidth)`，后跑的赢），
> offset 又从 0 变成 width，wrapperStyle 停在半开位。

- 修复：**整页收口改终止型**（只归零、不还原），恢复交给专门的 `restoreSwipeWidth()`，
  由页面在 `wx.nextTick` 里调用（隔一次真实渲染，宽度 observer 才真的跑过）。
  代价是这一帧元素 0 尺寸（不绘制），而此刻用户还看不到这一页 —— 比"可能留在半开位"安全得多。
- **单行补清与整页收口的诉求是相反的，已彻底分开**：
  整页 `resetSwipes` **不还原**（同批会覆盖）；单行 `forceCloseRow` **必须还原**（`rowResetTimer`），
  因为用户手指刚抬起、下一次触屏会打断过渡，且那一路 offset 本来就是 0、没有竞争。
- 常量：删掉 `SWIPE_RESET_FALLBACK_MS = 780`（那条弯路的方向本身就错），只留 `SWIPE_ROW_RESET_MS = 120`。
- 接口字段 `swipeResetTimer` → 改名 `rowResetTimer`（只服务单行路径；命名上就隔离掉误用）。
- 页面接线：两个列表页 `onShow` = `this.resetSwipes(); wx.nextTick(() => this.restoreSwipeWidth());`；
  `onHide` 由 `closeAllSwipes()` 改为 `resetSwipes()`（隐藏时不需要宽度，也就不必承担竞争风险）；
  `onUnload` 删掉不再需要的定时器清理。
