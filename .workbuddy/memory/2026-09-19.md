## 滑删几何修正 + 日期口径 + 两处闪烁（用户 5 条反馈）

### 1. 左右滑开的操作块外侧露空白（真根因：单位混用）
`van-swipe-cell` 的 `left-width` / `right-width` **单位是 px**（vendor 直接把值拼进 `translate3d(...px)`，
并用它夹取位移与判定 30% 开合阈值），而操作块宽度写的是 **144rpx**。
375 屏上 144px ≫ 72px → 卡片滑开 144px、块只有 72px，**块的外侧（屏幕那侧）必然空出一条**，左右两个方向都一样。

- 新增 `utils/rpx.ts`：`rpxToPx(rpx)`（750 基准）、`SWIPE_ACTION_WIDTH_RPX = 144`、`swipeActionWidth()`
- 两个列表页 data 加 `swipeWidth = swipeActionWidth()`，模板改成
  `left-width="{{ selecting ? 0 : swipeWidth }}"` / `right-width="{{ swipeWidth }}"`
- 这样"滑开距离 = 块宽"、块的外缘正好落在卡片闭合时的栅格线上，两侧都严丝合缝
- ⚠️ 这条推翻了之前技能里"宽度 = right-width 即可"的写法：两者必须**同单位**，跨单位要换算

### 2. 记账 / 记事的时间口径（用户确认）
相对说法只保留「今天 / 昨天」，且**始终带上月日**，不再有「前天」：
- `utils/group.ts` `dayLabel`：`今天 9月19日` / `昨天 9月18日` / `9月17日`（跨年带年份）
- `utils/date.ts` `fromNow`：同日 → 刚刚 / N分钟前 / N小时前；昨天 → `昨天 14:30`；
  更早 → `9月17日 14:30`（原来远期只给 `2026-09-01`，**把时分丢了**）
- 判断一律按自然日（不是经过小时数），避免"26 小时前"被说成昨天

### 3. 多选勾选圈"红底没铺满"
`.pick__box` 原来是 content-box：44rpx 内容盒 + 3rpx 边框，外圈靠边框补色，看着像没铺满。
- 改 `box-sizing: border-box`（44rpx 就是最终直径），勾改用 `van-icon name="success"`
  （不再依赖字体里的 ✓ 字形，字形在不同机型上会偏、会细）
- 顺手统一了 `note-item` 的待办勾选圈（同一问题），组件 json 注册 `van-icon`
- 三个位置：记账/记事行首选择位 + 多选操作条「全选」+ 记事待办勾选

### 4. 删除时其余记录"闪一下"（真 bug）
旧 `collapseRemove` 在动画结束时先 `setData({pinnedMap:{}, shrinkingMap:{}}, done)`：
这一帧把收起态复原，**而该行还在数据里** → 它长回满高，下面几行被顶下去；
下一帧 `done()` 才真正删数据 → 又跳回来。就是用户看到的"闪一下"。
- 修法：`refresh(extra)` 支持把额外字段并进**同一次 setData**；
  删除流程改成一次写完「移除该行 + 退出多选 + 清掉 pinnedMap/shrinkingMap」
- `collapseRemove` 的 `done` 只回调，不再自己清状态；文档写明这个契约

### 5. 多选态左滑退出瞬间闪出红色删除块
`exitSelect` 原来立刻 `clearPick()` → 右槽当场从「退出」换成**红色删除块**，
而 Vant 的收起是 0.6s 过渡 → 整个收起过程都在闪红。
- 修法：先 `closeAllSwipes()`，**等 620ms**（`SWIPE_CLOSE_MS`，vendor 写死 .6s + 余量）再 `clearPick()`
- 新增 `exitTimer` + `clearExitTimer()`，`onHide` / `onUnload` 清掉（避免切页后仍翻转状态）

## 手势互斥 / 即时退出 / 统计页回退（用户 3 条反馈）

### 1. 多选态左滑退出"有延迟不够灵敏"（上一版我自己引入的）
上一版为了让右槽不在收起动画里闪红，把 `clearPick()` 延后 620ms —— 结果**工具栏要等 0.6s 才收**，
手感发钝。改成"即时退出 + 中性色块接力"：
- `exitMap`：退出瞬间把刚滑开的那行记进去，**同一帧就翻转 `selecting`**（工具栏立刻收、够灵敏）
- 模板里右槽条件是 `selecting || exitMap[item.id]`：那一行在 0.6s 收起动画里继续显示灰色「退出」，
  动画结束再清 `exitMap` —— 全程不出现红色删除块
- exitMap 的清理放在 `clearExitTimer()` 里（`onHide` / `onUnload` 也会调用）
- 禁回归：`this.exitTimer = null;\n      this.clearPick();`（旧的"延迟翻转"写法）

### 2. 反向滑动不该翻到另一侧（新功能）
现象：单次左滑露出删除后再往右滑，如果滑得远一点，**多选块也会被露出来**。
根因：Vant 的 `swipeLeaveTransition` 在 offset 超过另一侧 `width × 0.3` 时会直接 `open(另一侧)`。
- `openSideMap: Record<id, 'left' | 'right'>`：记录每行当前滑开在哪一侧
- 模板把该行**另一侧的 width 置 0**：`left-width="{{ selecting || openSideMap[item.id] === 'right' ? 0 : swipeWidth }}"`
  → Vant 只能把 offset 收回 0，反向滑动就变成"仅仅收起"，两个方向对称成立
- ⚠️ 坑：**Vant 只在"滑开"时发 open 事件，收回去时不发任何通知**（内部 `swipeMove(0)`）。
  记录会因此变脏，而脏记录的后果是那一行另一侧宽度永远是 0、再也滑不出来。补两个清理点：
  - `bind:touchend="onCellTouchEnd"`：手指离开后读实例的 `offset`，仍非 0 才保留记录（覆盖"滑回去收起"）
  - `bind:click="onCellTap"`：点内容会关闭且发生在 touchend 之后，只能靠这个事件补清
- `closeAllSwipes` / `enterSelect` / 删除流程的三处 setData 都会一并清 `openSideMap`

### 3. 统计页"选择时间后没有真正改变效果"（第 4 次外部回退）
外部工具把 `pages/stats/index.ts` 的 `refresh()` **单独回退成了"只按月"的旧版**：
`goDay` / `onPickDate` / 上下一天 / 「看整月」全都还在，`month` 也能改，
但 refresh 压根不看 `mode` / `date` —— 所以选了日期界面纹丝不动。
**注意：这种回退 tsc 与单测都发现不了**（旧实现本身是合法 TS，页面的单测也不覆盖页面逻辑），
只有标记复核能抓到。已恢复按粒度过滤的 refresh，并顺手修掉一个隐患：
单日模式下把 `month` 钉到所选日期所在月，「看整月」才会回到正确的那一个月。
- 新增标记：`const scoped = ledgerStore.records.filter`、`goDay(date: string) {`、`bindchange="onPickDate"`
- 新增禁回归：`const monthRecords = ledgerStore.records.filter`（旧的只按月写法）

## 主题切换 / 首页改造 / 额度进度条（用户 8 条需求）

### ⚠️ 最重要的发现：编辑"部分丢失"的根因是**并行改同一文件**
本轮又发生多次"回执成功但内容没变"（`StorageKeys.BudgetNotice`、`budgetAlert()` 实现、
`takeNavIntent` 导入、`todoBar` 字段、`settingsSummary` 移除、`app.wxss` 的 `.summary__budget` 都丢过）。

## 三处反馈的根因定位（用户 3 条）

### 1. 首页「去记账 / 去记事」只停在列表页，没打开编写页

方法存在、`tsc` 通过、标记里的 `openEditorFromIntent` 也命中 —— 所以静态检查全绿，功能就是不通。
- 补齐两处调用点，并把"打开编辑页"做得更稳：`wx.nextTick(go)` 先试一次 + `setTimeout(go, 120)` 兜底重试，
  用 `done` 标记与 `navigateTo` 的 `fail` 回调保证"最终只会压进一个编辑页"（成功过的不再补跳）

被 `fail: () => {}` 吞掉 → 表现为毫无反应）。而"在设置页里切主题"正好发生在二级页上，

  从设置页返回 tab 页的 `onShow` 就会把 tab 栏刷对。幂等，重复调用无副作用

## 两个 bug：记账保存卡死 + 统计明细改用记账卡片（用户最后一轮）

### 1. 记账保存后不返回（真 bug，根因：去重跳过不触发回调）
`pages/ledger/edit/index.ts` 的 `onSubmit` 超额分支：`showBudgetAlertOnce(alert, () => wx.navigateBack())`
——弹窗的回调里才返回。但 `showBudgetAlertOnce` 在**当天已弹过一次**（`shouldNoticeToday` 为 false）时
直接 `return false`、**不触发 `onClose` 回调**，于是 `navigateBack` 不执行，用户卡在编辑页。
- 修法：延迟后 `const shown = showBudgetAlertOnce(alert, () => wx.navigateBack()); if (!shown) wx.navigateBack();`
  —— 真弹了就等关闭再返回，去重跳过就直接返回。两条路径都能回去。
- **教训**：`showBudgetAlertOnce` 的返回值是"是否真的弹了"，不是"是否超额"。回调只在真弹时触发，
  调用方若依赖回调做收尾，必须处理"返回 false 但逻辑仍需继续"的分支。

## 记账保存后"立即返回"（去掉延迟）

用户反馈：保存成功（出现「已保存」toast）后有明显延迟、没有立即返回页面。

**根因**：`pages/ledger/edit/index.ts` 的 `onSubmit` 里有两处 `setTimeout` 延迟——
正常分支 `BACK_DELAY=500ms`、超额分支 `ALERT_DELAY=1300ms`。本来是想"等 toast 显示/避免弹窗突兀"，
但 `wx.showToast` 和 `wx.showModal` 都是**全局的**，返回上一页后照常显示，根本不需要用延迟来"让它们有机会显示"。

**修法**（用户确认超额弹窗也「立即返回后弹」）：
- 删掉 `BACK_DELAY` / `ALERT_DELAY` 两个常量、`backTimer` / `alertTimer` 两个定时器字段
  （接口声明 + Page 初始化 + onUnload 清理一起移除）。
- `onSubmit` 尾部统一为：`haptic('medium')` → `showToast('已保存')` → 超额则 `showBudgetAlertOnce(alert)`（不传回调）→ `wx.navigateBack()`。
  立即返回，toast 与弹窗都在返回后的页面正常显示。
- **教训**：`wx.showToast` / `wx.showModal` 是全局 API，不随页面 `navigateBack` 销毁；
  想让"提示"在返回后仍可见，不需要也不应该用 `setTimeout` 延迟跳转，直接跳即可。

### ⚠️ 修正：「返回后弹」弹不出来 → 回到「本页弹完再返回」（但无延迟）
上一版改成 `showToast → showModal → navigateBack`（先返回、返回后弹弹窗），实测**超额弹窗直接没了**。
根因：`wx.showModal` 若在 `navigateBack` 前后几乎同时调用，页面卸载会把它一起吞掉——
"返回后弹"这个时序在微信里不可靠（toast 能活，modal 未必）。
- 最终口径：**不超额 → 立即 `navigateBack`（无延迟）；超额 → 立即 `showBudgetAlertOnce(alert, cb)`（不延迟、不先返回），
  弹窗关闭后 `cb` 再 `navigateBack`；去重跳过（当天已弹过）时 `shown=false` → 立即返回**。
- 关键经验：**`wx.showModal` 要留在触发它的页面生命周期内弹**；跨页面卸载弹 modal 会被吞，
  而 `wx.showToast` 则相对能跨页面存活。二者对 `navigateBack` 的容忍度不同，别混为一谈。

## 新增记录默认分类未写入 tag → 统计页显示「未分类/其他」

用户反馈：新添加记录（默认分类）保存后，统计页显示成「其他 / 未分类」。

**根因**（`pages/ledger/edit/index.ts` 的 `onLoad`）：初始选中项只写了
`this.sel = tagStore.tags.indexOf(wanted)`（标签条上的高亮下标），**从没把 `data.tag` 同步成选中标签**。
`data.tag` 初值是 `''`，提交时 `input.tag = d.tag = ''`，保存的记录 `tag` 为空 → 统计页 `labelOf` 归「未分类」。
而且 `wanted = initialTag || tagStore.center` 里，首次使用 `center` 是空串（`getCenter()` 未存储返回 `''`），
`indexOf('') = -1`，`sel = -1`——首次新增时连默认高亮都没有。

**修法**：
- `wanted` 加回退到 `tagStore.tags[0]`（与注释「> 第一项」一致，保证新增记录有默认分类）。
- 新增模式（`!this.data.isEdit`）且 `sel >= 0` 时，把 `tagStore.tags[sel]` 写进 `data.tag`（`patch.tag`）。
- 编辑模式不覆盖 `tag`（分支里已设过，避免覆盖掉"已不在当前列表里的旧标签"）。

**教训（同「方法在、调用没落盘」一类）**：设置"选中态"（`sel`/高亮）≠ 设置"业务字段"（`data.tag`）。
UI 高亮和真正提交的数据是两套东西，改其中一套必须检查另一套是否同步。

## 超额提醒改回「返回后再弹」（用户最终口径，2026-09-19 晚）

用户明确：超额弹窗要**在返回上一页之后**再弹出来。

**为什么这次能成**（此前"返回后弹"实测弹不出来）：那次是 `showModal` 与 `navigateBack` **同步紧挨着**执行，
页面卸载把 modal 吞了。这次改成 `navigateBack()` 之后 **`setTimeout` 约 600ms**（页面切换动画走完）
再 `showBudgetAlertOnce(alert)`——modal 在返回后的页面上稳定显示。结论修正为：
**`wx.showModal` 不是不能跨页面，而是不能与页面卸载"贴脸"竞争；给一拍过渡时间即可跨页弹。**
（`wx.showToast` 依旧无所谓时序，能跨页存活。）

- `onSubmit` 尾部：`haptic → showToast('已保存') → 超额则 setTimeout(600) 弹提醒 → wx.navigateBack()`。
  定时器**不登记、不清理**：回调只是全局弹窗 + 去重写存储，页面卸载后执行也无副作用；
  若在 onUnload 里 clearTimeout 反而会把弹窗取消掉。
- 去重兜底：若返回的是首页，其 `onShow` 的 `noticeBudget()` 可能先用同一个去重键抢先弹，
  600ms 后这里的那次会被去重跳过——总之**当天只弹一次**，两条路径都能看到弹窗。
