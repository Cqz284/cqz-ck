## 用户发来 DevTools 截图后定位：编辑器 TS 版本旧 + 全项目清理行内 type 导入

截图关键信息：DevTools「问题」面板 18 个报错，全部集中在 `pages/index/index.ts` 等文件，典型三条是

- `ts(1005) 应为 ","` 卡在 `import { createStoreBindings, type StoreBindings }` 的 `type` 位置
- `ts(2305) 模块 "mobx-miniprogram-bindings" 没有导出的成员 "StoreBindings"`
- `ts(2300) 标识符"重复"`

**根因**：DevTools 编辑器内置的 TS 比本地 5.6.3 旧，不认识 **行内 type 修饰符**（`import { a, type B }`，TS 4.5+ 语法）。
解析在 `type` 处失败后，`type` 被当成普通标识符，于是级联出"重复标识符""没有导出成员"等一堆假错。
（本地 `tsc --noEmit` 一直是通过的，所以这是编辑器诊断层的版本差异，不是代码错。）

**处理**：把全项目 **16 个文件 21 处**行内 `type` 修饰符，统一改写为独立的 `import type { ... } from '...'` 语句
（TS 3.8+ 语法，也是本项目 `store/ledger.store.ts` 一直在用的写法）。
用脚本按 import 语句整体重写（值导入在前、类型导入紧随其后），避开正则逐词替换的坑。
改写后：`tsc --noEmit` 通过、`jest --ci` 12 suites / 165 tests 通过、全项目再无行内 type 修饰符。
顺带修正了自己的校验脚本（原先把 `van-button`/`navigation-bar` 当自闭合标签，产生假告警）——全项目 WXML 标签配平 ✓
